飞书 SSO 后端对接文档

Value Partners Product Center — 飞书单点登录后端对接指南，涵盖飞书开放平台配置、JustAuth 集成、回调逻辑、接口契约和联调测试。

概述

本文档面向后端开发团队，说明如何为 Value Partners Product Center 系统接入飞书（Feishu/Lark）SSO 单点登录。

前端已完成的工作：

  • 登录页已添加飞书登录入口（蓝色飞书图标）
  • OAuth 跳转、回调处理、账号绑定 UI 均已就绪
  • 前端使用 source = "FEISHU" 标识飞书来源

后端需要完成的工作：

  1. 飞书开放平台创建企业自建应用
  2. JustAuth 配置飞书 OAuth 参数
  3. 回调逻辑中实现自动创建账号 + 分配默认角色
  4. 创建"访客"默认角色

整体架构

登录流程

用户点击飞书图标
    ↓
前端调用 GET /auth/binding/FEISHU
    ↓
后端返回飞书授权 URL
    ↓
前端 window.location.href 跳转到飞书
    ↓
用户在飞书登录并授权
    ↓
飞书回调 /social-callback?code=xxx&state=xxx&source=FEISHU
    ↓
前端提取 code/state/source，调用 authLogin({ grantType:'social', socialCode, socialState, source:'FEISHU' })
    ↓
后端处理：
  1. 用 code 换 access_token
  2. 用 access_token 获取飞书用户信息
  3. 查 sys_user 是否有匹配账号
     ├── 有 → 直接登录，返回 token
     └── 没有 → 自动创建 sys_user + 分配默认角色 → 返回 token
    ↓
前端登录成功，跳转到首页

一、飞书开放平台配置

1.1 创建应用

  1. 登录 飞书开放平台
  2. 进入「开发者后台」→「创建企业自建应用」
  3. 填写应用名称（如 Value Partners Product Center）和描述
  4. 记录 App ID 和 App Secret

1.2 配置安全设置

在应用详情页 →「安全设置」中添加重定向 URL：

https://你的域名/social-callback

1.3 申请权限范围

在「权限管理」中申请以下权限：

权限scope用途
获取用户基本信息默认姓名、头像、open_id
获取用户邮箱contact:user.email:readonly用于匹配系统账号
获取用户手机号contact:user.phone:readonly备选匹配方式
获取用户工号contact:user.employee_id:readonly备选匹配方式

1.4 发布应用

配置完成后，提交应用审核并发布。发布后组织内用户才能使用。

⚠️ 注意：重定向 URL 必须与后端 JustAuth 配置中的 redirect-uri 一致。本地开发可用 http://localhost:5666/social-callback。

二、后端 JustAuth 配置

ruoyi-plus 后端已集成 JustAuth，只需在配置文件中添加飞书配置。

2.1 application.yml 配置

justauth:
  type:
    FEISHU:
      client-id: 你的飞书App_ID
      client-secret: 你的飞书App_Secret
      redirect-uri: https://你的域名/auth/callback/feishu

2.2 关键参数说明

参数说明示例
client-id飞书 App IDcli_a5xxxxxxxxxxxxx
client-secret飞书 App Secretxxxxxxxxxxxxxxxxxxxxxx
redirect-uriOAuth 回调地址（后端接收飞书回调的地址）https://your-domain/auth/callback/feishu
⚠️ source 名称必须为 FEISHU（大写），与前端 oauth-common.tsx 中配置的 source: 'FEISHU' 保持一致。

2.3 飞书 OAuth2 端点

JustAuth 已内置飞书支持，以下是飞书的 OAuth2 端点供参考：

端点URL
授权https://open.feishu.cn/open-apis/authen/v1/authorize
获取 Tokenhttps://open.feishu.cn/open-apis/authen/v2/oauth/token
获取用户信息https://open.feishu.cn/open-apis/authen/v1/user_info

三、回调处理逻辑

后端在收到飞书回调后，需要完成以下步骤：

3.1 标准流程

1. 接收飞书回调的 code 参数
2. 用 code + App ID + App Secret 调用飞书 Token API 换取 access_token
3. 用 access_token 调用飞书 User Info API 获取用户信息
4. 用飞书用户信息匹配/创建系统账号
5. 返回系统 token 给前端

3.3 自动创建账号逻辑

建议在社交登录回调处理中实现以下逻辑：

// 伪代码
AuthUser feishuUser = justAuth回调获取的飞书用户;
String email = feishuUser.getEmail();
String name = feishuUser.getNickname();
String avatar = feishuUser.getAvatar();
String openId = feishuUser.getUuid();

// 1. 查找社交绑定记录
SysSocialUser socialUser = socialUserMapper.selectBySourceAndUuid("FEISHU", openId);
if (socialUser != null) {
    // 已绑定，直接用关联的系统用户登录
    return login(socialUser.getUserId());
}

// 2. 查找是否有匹配邮箱的系统用户
SysUser existingUser = userMapper.selectByEmail(email);
if (existingUser != null) {
    // 匹配到已有用户，自动绑定并登录
    createSocialBinding("FEISHU", openId, existingUser.getUserId());
    return login(existingUser.getUserId());
}

// 3. 没有匹配，自动创建新用户
SysUser newUser = new SysUser();
newUser.setUserName(email);
newUser.setNickName(name);
newUser.setEmail(email);
newUser.setAvatar(avatar);
newUser.setPassword(随机密码);  // SSO 用户不需要密码
newUser.setStatus("0");  // 正常状态
userMapper.insert(newUser);

// 4. 分配默认角色（访客）
userRoleMapper.insert(newUser.getUserId(), 访客角色Id);

// 5. 创建社交绑定
createSocialBinding("FEISHU", openId, newUser.getUserId());

// 6. 登录
return login(newUser.getUserId());

3.4 默认角色配置

在 sys_role 表中创建"访客"角色：

字段值

role_keyguest
role_sort99
status0（正常）

访客角色的菜单权限（sys_role_menu）只分配查看权限：

权限码说明

productcenter:productCenterMasterdata:queryProduct Team 详情查看
productcenter:productCenterData:listOperational Team 列表查看

四、前后端接口契约

以下接口已存在于 ruoyi-plus 中，前端飞书 SSO 复用这些接口，不需要新增接口。

4.1 获取授权跳转 URL

GET /auth/binding/FEISHU?domain=xxx&tenantId=xxx

Response: "https://open.feishu.cn/open-apis/authen/v1/authorize?..."

后端根据 FEISHU source 查找 JustAuth 配置，生成飞书授权 URL 返回给前端。

4.2 社交登录

POST /auth/login
Content-Type: application/json

{
  "grantType": "social",
  "socialCode": "飞书回调返回的code",
  "socialState": "飞书回调返回的state",
  "source": "FEISHU",
  "tenantId": "000000"
}

Response:
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiJ9..."
  }
}

后端用 socialCode 和 source 完成飞书 OAuth 流程，匹配/创建用户，返回系统 token。

4.3 已登录用户绑定社交账号

POST /auth/social/callback
Content-Type: application/json
Header: Authorization: Bearer {access_token}

{
  "socialCode": "飞书回调返回的code",
  "socialState": "飞书回调返回的state",
  "source": "FEISHU",
  "tenantId": "000000"
}

已登录用户在「个人中心 → 账号绑定」中绑定飞书账号。

六、联调测试步骤

6.1 本地测试

  1. 后端启动，配置飞书 JustAuth 参数
  2. 前端 pnpm dev 启动
  3. 登录页点击飞书图标
  4. 应跳转到飞书授权页面
  5. 登录并授权后，应回调到 /social-callback
  6. 验证：首次登录自动创建账号，分配访客角色
  7. 验证：再次登录直接进入系统

6.2 测试场景

场景预期结果
首次飞书登录（无系统账号）自动创建账号 + 访客角色 + 登录成功
再次飞书登录直接登录，不重复创建
已登录绑定飞书个人中心绑定成功
管理员手动提权后登录显示对应菜单和权限
飞书账号无权限只能查看，不能增删改

七、常见问题

问题原因解决方案
点击飞书图标无反应后端未配置 FEISHU JustAuth检查 application.yml 配置
飞书授权后白屏回调地址不匹配确认 redirect-uri 与飞书安全设置一致
回调报错 invalid code授权码过期（5分钟）重新授权
登录后无菜单访客角色未分配菜单权限检查 sys_role_menu 配置
头像不显示飞书头像 URL 可能需要翻墙后端下载头像上传到 OSS
source 不匹配前后端 source 大小写不一致确认统一使用 FEISHU（大写）
