1. General Conventions

1.1 Date Format

All date fields use YYYY/MM/DD format (e.g. 2026/05/16).

Exception: latestTerDate uses month picker (picker="month") but still submits YYYY/MM/DD (day=01).

Excel import accepts 6 formats (auto-normalized to YYYY/MM/DD):

PriorityFormatExampleNote
1DD-MMM-YYYY05-May-20253-letter month (Jan–Dec)
2YYYY/MM/DD2026/05/16Preferred
3YYYY-MM-DD2026-05-16ISO variant
4DD/MM/YYYY16/05/2026HK client priority
5MM/DD/YYYY05/16/2026Fallback
6M/D/YY5/16/26Excel auto-format
Ambiguous dates (e.g. 05/06/2026) are resolved as DD/MM/YYYY first (HK preference). If parsing fails, fallback to MM/DD/YYYY.

1.2 Composite Time+TZ Format

Storage format: HH:mm CCC — single string, e.g. 16:00 HKG.

Form: TimePicker (HH:mm) + Select (3-letter code). Both required.

Valid timezone codes:

GMT HKG IRL CHN AUS CAN FRA DEU JPN LUX SGP CHE TWN GBR USA

1.3 Boolean Fields

ContextTrueFalse
Form dropdowntrue (label: Yes)false (label: No)
Excel import"true" / "TRUE""false" / "FALSE"

1.4 Multi-Select Fields

Stored as comma-separated strings, split/join on form submit/backfill.

FieldModuleExample
businessCalendarOperational"Hong Kong,Taiwan,Japan"
pricingMethodologyOperational"Amortization,Mark to Market"

1.5 Numeric Types

TypeRegexExample
Integer (non-negative)/^\d+$/5, 100
Decimal 2dp (non-negative)/^\d+(\.\d{1,2})?$/1.50, 0.25
Numeric (non-negative)Number(x) >= 01000, 99.999

1.6 Excel Import Notes

Parsing: { defval: '', raw: false, dateNF: 'yyyy/mm/dd' } — all values as text (preserves leading zeros in codes).
Required validation: only enforced for importMode === 'add data'; skipped for update modes.
Date auto-normalize: passed dates are standardized to YYYY/MM/DD before sending to backend.
Dash skip: a single - in any optional field is converted to null (skips validation). Required fields still reject -.
