1. Overview — What Are Composite Fields?

The three fields cutoffTime, dealingCutOff, and valuationPoint each store two pieces of information in a single string:

  • Time — e.g. 16:00 (HH:mm, 24-hour format)
  • Timezone/Country Code — e.g. HKG (ISO 3166-1 alpha-3 country code)

They are combined into a single string with a space separator:

"16:00 HKG"
"09:30 IRL"
"15:00 SGP"
Key Rule: The backend stores and returns these as a single VARCHAR/string field. Do NOT split into separate columns. Do NOT add a separator other than a single space.

4.2 What the Frontend Does

The frontend automatically splits the string into two parts for the form UI:

// Frontend transformShareClassData() — reading for edit form
const raw = "16:00 HKG";
const parts = raw.trim().split(/\s+/);
// parts[0] = "16:00" → displayed in TimePicker
// parts[1] = "HKG"  → displayed in Select dropdown

4.3 Null Response

If the value is NULL in the database, return null (or omit the field):

}

5. Write (API Request) — Frontend → Backend

When the frontend submits data (POST/PUT), it sends the field as a single string:

5.1 Request Format

{
  "dealingCutOff": "16:00 HKG",
  "valuationPoint": "18:00 IRL",
  "cutoffTime": "15:30 SGP"
}
Backend: DO NOT parse or transform this value. Store it directly as-is into the VARCHAR column. No date parsing, no timezone conversion.

5.2 What the Frontend Does Before Sending

// Frontend submit handler — combines two form fields into one string
const timeStr = dayjs(dealingCutOff_time).format("HH:mm"); // e.g. "16:00"
const tz      = dealingCutOff_tz;                          // e.g. "HKG"
submitData.dealingCutOff = [timeStr, tz].filter(Boolean).join(" ");
// Result: "16:00 HKG"

// _time and _tz are removed before sending
delete submitData.dealingCutOff_time;
delete submitData.dealingCutOff_tz;

5.3 Null Request

If both time and tz are empty, the frontend sends null:

{
  "dealingCutOff": null
}

6.2 Import (Excel → Backend)

Users fill the same format in Excel. The backend should:

  1. Read the cell value as a string
  2. Trim whitespace
  3. Validate format: ^(\d{2}:\d{2})\s+([A-Z]{3})$
  4. Store as-is into the database
Note: If the user enters 16:00HKG (missing space) or 16:00 Hong Kong (full name), the import should reject the row with a validation error.

6.3 Validation Regex for Import

// Java regex for validating imported value
private static final String TIME_TZ_PATTERN = "^(\\d{2}:\\d{2})\\s+([A-Z]{3})$";

// Valid:  "16:00 HKG", "09:30 IRL", "15:00 SGP"
// Invalid: "16:00HKG", "16:00 Hong Kong", "1600 HKG", ""
